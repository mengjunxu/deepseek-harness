## ChatGPT integration facts

- Usage classification: SIWC uses Codex / ChatGPT Work usage, planned as `work_codex_shared`, not ordinary ChatGPT chat allowance. OAuth identity alone does not establish billing. Verification: [official OpenAI explanation](https://learn.chatgpt.com/docs/sign-in-with-chatgpt), checked 2026-10-26; restrictions and route mechanics belong to the [provider matrix](../docs/legacy/dsh/spikes/model-provider-matrix.md). Balance stays `unknown` unless actually available; this documented rule does not imply the quota-policy implementation exists.
- Model and executor roles: `llm-pi-ai` / opt-in `chatgpt-plan` supply models to the DSH loop; `subagent-codex` runs the native Codex app-server loop; Codely/MGSD local examples run external processes. Verification: source audit 2026-10-26, [reuse matrix and Decision Log](../docs/workflows/DSH_IMPLEMENTATION_PLAN.md). A Codely native-model provider is a target requiring evidence, not something established by its CLI example.
- State ownership: Session JSONL, MGSD TaskFact/SQLite and existing jobs/workflow are reuse candidates for the product plan. `.ai/` holds developer collaboration records, not the runtime Task Store. A DSH context import/Fork neither restores an official ChatGPT Session nor synchronizes its Memory. See [workflow](WORKFLOW.md), [architecture](ARCHITECTURE.md) and the plan's ownership mapping.
- Entry direction: optional ChatGPT → DSH MCP/Tunnel is distinct from DSH → model inference. The vNext.4 plan targets a peer Web Provider with gated availability and `chatgpt_web_unofficial` usage, distinct from `chatgpt_regular`; real access remains unverified and requires separate admission. These are target constraints in the plan; an MCP client or resources package does not establish that the planned inbound gateway is implemented.
- Reference DEV transport: codex-chatgpt-web 6.1.17 isolates browser/Codex data with `--dev-profile` and `CODEX_WEB_GPT_DEV_HOME`; `startServer` rejects `dev-harness` Responses listeners, while its DEV driver uses the in-process Responses handler and Browser Adapter. DSH cannot treat this profile as a ready OpenAI baseURL or remove its purpose check. Verification: scoped source review and reference isolation/worker tests on 2026-11-01; [PoC checkpoint](tasks/dsh-web-provider-poc/handoff.md). This does not establish real Web or DSH admission success.
- Reference request mapping: the 6.1.17 browser replay requires matching thread/Turn metadata on the current user message; its no-local-tools warning is a `text_delta` with `phase: commentary`, distinct from the final answer. Verification: real DEV Responses handler probe on 2026-11-01, [evidence](tasks/dsh-web-provider-poc/evidence/reference-stream.json) and [preflight rejection](tasks/dsh-web-provider-poc/evidence/reference-preflight-rejection.json). These are reference protocol facts, not a shipped DSH Web integration.

- Bounded Web validation: process-local registration grants bind an explicitly selected non-default Harness home, route, model allowlist, expiry and preparation budget. Replacement does not renew budget and revokes old reservations; ordinary Web policies remain gated. See the [LLM README](../packages/llm/llm/README.md) and [PoC checkpoint](tasks/dsh-web-provider-poc/handoff.md). Verified with focused tests and keyless SDK replay on 2026-11-01; this is not evidence of a live DSH Web adapter.
- Reference in-process console noise: the 6.1.17 reference logs through `console.info` (e.g. `[chatgpt-web]` / `[chatgpt-web-helper]` lines), sharing the hosting process's stdout; any in-process probe multiplexing a stdout line protocol must redirect console output to stderr or tolerate non-JSON lines, or the first log line breaks the protocol reader. Verification: bridge worker real-run debugging on 2026-11-02, [PoC checkpoint](tasks/dsh-web-provider-poc/handoff.md).

## Built-runtime plugin loading

- Type stripping loads `.ts` plugins: the built `dsh` CLI imports `.ts` profile plugins through Node 22.18 native type stripping, so constructor parameter properties (`constructor(private readonly x: T)`) fail with `Type stripping does not support parameter properties`; declare the fields and assign them in the body. Type-only imports from package sources are erased and stay safe. Verification: bridge fixture boot loop on 2026-11-02, [PoC checkpoint](tasks/dsh-web-provider-poc/handoff.md).
- Patch plugin paths: in a `--patch` entry list, an `insert[].name` starting with `.` resolves against the patch file's own directory; absolute `file://` names fail to import in the built runtime. Generate run patches where the relative path to the plugin is stable. Verification: same bridge boot loop on 2026-11-02.
